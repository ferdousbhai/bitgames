## Pass and release procedure

- For a generated adventure, read its entry in `examples/_studio/catalogue.mjs`, its activity module under `examples/_studio/runtime/`, its generated `game.json`, and [the studio guide](../examples/_studio/README.md). Scan all three difficulties and all five steps, including wrong answers and recovery. Use phone portrait, short landscape, iPad both ways, and the live store. The repo's `.agents/skills/review-games/SKILL.md` has useful content criteria in its Decide section.
- Change the design, runtime, or Blender builder source, then run `pnpm examples:build`. The build copies shared runtime into all 88 generated `public/` directories. Do not hand-edit those outputs. For a runtime change, run `pnpm examples:check`, the generated-game browser playthrough (`node examples/_studio/tests/browser.mjs --browser chromium`), `quality.mjs`, `second-quality.mjs`, `navigation.mjs`, and WebKit smoke. `EXAMPLES_PORT=4213 node examples/_studio/serve.mjs` serves the local catalogue; set `EXAMPLES_ORIGIN` to match.
- Stage only intended game paths under `examples/` plus authorized policy/pass documents (never unrelated `apps/` changes), commit the source and generated output, then `node examples/publish.mjs <id>`. Run `pnpm examples:build` again to copy the new URL into `examples/catalogue/games.json`, commit the URL changes, check `git status --short examples` for any other uncommitted game URL, then run `pnpm --dir apps/store seed:remote`. Confirm `listed <id>`, push, and test the deployed URL and store Play link. A first pass still needs a release if it finds no code change.
- Shared runtime or shared toy-builder edits can leave already listed adventures serving stale bytes. After the affected game's loop, republish each affected listed adventure. Never call a browser-only pass proof of real iPad performance.

The previous loops' working notes live in `~/.cache/bitgames-polish/` on this machine. Their constraints remain useful: do not use `git stash`, `reset`, `checkout`, `restore`, or `clean` in a shared checkout; do not stop another session's server; do not stage `apps/` as part of the game loop. The store app may be edited concurrently. Check `git status --short` before each commit and stage by path. If a push is rejected, stop and report it instead of pulling with autostash.
